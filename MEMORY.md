## 2026-10-10: Fixed figure-numbering bug by removing the one real float

- The maintainer: figure numbers "not incrementing for the first two," recalled this as a persistent, never-fixed bug in the legacy project too.
- Root cause: Pattern 1 (forecast figure) was the only one of the three main-text figures using a genuine floating `figure` environment; Patterns 2 and 3 use `\captionof{figure}{...}` with no float. Real floats don't understand `paracol`'s column structure -- LaTeX's placement algorithm can defer or reorder a float relative to the non-floating content around it, so its caption can end up rendered out of the sequence its counter value implies. That reads as "the numbers are wrong" even though each counter step is individually correct.
- Confirmed by re-checking the real legacy `content.tex`: every one of its actual in-flow figures (small/medium/large) uses plain `\captionof{figure}{...}`, never a `\begin{figure}` float. The only float-based figure example in the legacy source was `figures/_figure.tex`, a generic template snippet never actually used in the real paper's content -- which is where Pattern 1 was mistakenly modeled from. That explains the maintainer's memory of this as unresolved: the real content always avoided the float, the broken snippet was just never fixed because nothing needed it.
- Fix: Pattern 1 now uses the same non-floating `\captionof{figure}{...}` technique as Patterns 2 and 3 -- an image in a plain `\begin{center}`, no float wrapper. All three main-text figures are now float-free and strictly ordered by source position.
- Not yet checked: the table pattern still uses a real `\begin{table}` float, which could have the same class of problem inside paracol. Not reported as broken and out of scope for this fix, but flagged as a likely next issue if tables ever get added near figures.

## 2026-10-10: Figure numbering actually fixed — paracol counters are column-local

- **Corrects the entry immediately above**, which blamed the numbering bug on the floating `figure` environment. That diagnosis was wrong; the bug survived that change. (The float removal is kept anyway — it matches the real legacy `content.tex`, which never floats in-flow figures — but it was not the cause.)
- Real cause, confirmed by reading `paracol.sty` rather than reasoning from symptoms: line 2293 ships `\gdef\pcol@gcounters{\@elt{page}}` — paracol's list of *global* counters contains only `page`. **Every other counter, `figure` included, is column-local**, so each column holds its own copy. A figure written inside a column and one written in a `\switchcolumn[1]*[...]` spanning block are stepped in different counter states, so the spanning side-caption figure restarted at 1 after the in-column figure had already taken 1 — rendering 1, 1, 2 across the three figures.
- Fix: `\globalcounter*` (paracol's own documented mechanism) as a new final section 19 of `config.tex`. It must stay last in the file: the starred form snapshots the counter list at the moment it is called, so every counter-defining package (theorems, listings, tcolorbox's `boxstory`) has to be loaded first.
- Considered and rejected: dropping the spanning side-caption pattern entirely to keep all figures in one column. That would have traded away the caption-into-sidebar look — the detail that makes the layout match the real article — to dodge something one documented line resolves.
- Lesson worth keeping: two wrong guesses here came from reasoning about LaTeX behaviour from symptoms; the right answer came from reading the package source. For layout bugs in an unfamiliar package, read the `.sty` first.

## 2026-10-10: Table captions fixed, appendix width, bold subsections

- **Caption-leak bug.** `\captionsetup[table]` carried `width=\textwidth`. Inside paracol `\textwidth` is still the whole page width, not the column being typeset, so every TableM caption was set page-wide and ran out of the text column into the sidebar. Removed; left unset, a caption takes the width of whatever contains it, which is right for both TableM (column) and TableL (span). The same `width=\textwidth` was sitting in the `lstlisting` caption style and was removed too -- identical latent bug, not yet visible only because no listing is used.
- Table environments now wrap their body in `threeparttable`, so a `tablenotes` block works without scaffolding and the caption is tied to the table's width.
- Tying the caption to the table width then exposed the other half: a hand-sized tabular is narrower than the column, so the caption ended short of the text block. Added `tabularx` plus an `L` column type (`>{\raggedright\arraybackslash}X`) and moved the example tables onto `\begin{tabularx}{\linewidth}`, so the table fills the text width and caption, rules and notes all stay flush. This is deterministic, unlike hand-tuned `p{}` widths which break the moment the column ratio changes.
- Dropped `\rowcolors` alternating shading from every example table. `xcolor`'s `table` option is left loaded so authors can still add shading if they want it.
- Appendix now runs at the same width as the main text: removed the `adjustwidth` wrapper and the `\appendixtab` macro that existed only to feed it. The only remaining difference is the smaller type `\BeginAppendix` sets, which is the intent.
- `\subsection` headings are now bold, matching `\section`. `\subsubsection` deliberately left unbolded -- only subsections were asked for, and it still reads as a distinct third level.
- Verified by compiling and reading the pages: exit 0, no errors, no undefined references, zero overfull hboxes, 9 pages. Table 1 and its note sit flush with the text column, Table 2 spans margin to margin, appendix body and Table A.1 match the main text width, subsection headings render bold.

## 2026-10-10: Stage B -- TOML metadata system and the generated cover

- Replaces `authors.json` / `authors.tex` / `build_authors.py`, all three now deleted. Metadata lives in **`journal.toml`** (journal names, logos, editor-in-chief, licence), **`article.toml`** (title, abstracts, keywords, highlights, DOI, volume, issue, dates, acknowledgements, language, draft flag) and **`authors.toml`** (authors and affiliations). `build_cover.py` reads all three with stdlib `tomllib` and writes **`cover.tex`**.
- Split rationale, since the maintainer was unsure about it: the editor-in-chief is a journal officer and sits in `journal.toml`, while the *associated* editor handles one specific article and sits in `article.toml`. Ownership, not just topic, decides the file.
- `cover.tex` holds **data macros only**; the layout stays in `config.tex` (`\PrintMasthead`, `\PrintAbstracts`, `\PrintSidebar`, `\PrintLicense`). Keeping styling out of a generated file means editors can retune the cover without touching the generator, and `cover.tex` never needs hand-editing.
- Ordering constraint: `main.tex` must `\input{cover}` *before* `\input{config}`, because config acts on `\DocLanguage` and `\IsDraft` while loading. Both now come from `article.toml` rather than being typed into `main.tex`, so `main.tex` no longer contains any article data at all.
